# 0003. `-s` を接続全体の締め切りにする

- ステータス: 承認
- 日付: 2026-11-07

## 背景

接続ごと・読み込みごとにタイムアウトをかけると、DNS が複数のアドレスを返す場合や、少しずつしかデータを返さないサーバーの場合に、合計の待ち時間が `-s` を大きく超える。IPv6 が通らない環境で AAAA と A の両方を返すホストでは、毎回ほぼ倍の時間がかかる。

## 決定

- `-s` は、TCP 接続から TLS ハンドシェイク完了までの全体に 1 つの締め切りとしてかける。
- 複数のアドレスがある場合は、残り時間を未試行のアドレス数で等分して各接続に割り当てる。
- ハンドシェイクは自前のループで進め、1 ステップごとにソケットのタイムアウトを残り時間に設定し直す。
- DNS の名前解決は締め切りに含めない。標準ライブラリには getaddrinfo に上限をかける手段がなく、そのために解決用のスレッドを足すほどの価値はないと判断した。
- `-s 0` と、表現できないほど大きな値は「上限なし」として扱う。

## 結果

- 応答しないサーバーや少しずつ返すサーバーに対しても、`-s` 秒前後で Error 欄にタイムアウトが出る。
- DNS の応答が遅いホストでは、`-s` より長く待つことがある。
- TLS 1.3 では、ハンドシェイク完了の判定（is_handshaking）が最後の送信より先に false になるため、送信待ちのデータがある間はループを続ける必要がある。
