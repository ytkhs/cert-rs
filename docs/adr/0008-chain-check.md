# 0008. `--chain` でサーバーが送った証明書チェーンを検査する

- ステータス: 承認（一部を [0009](0009-chain-check-revisions.md) で置き換え）
- 日付: 2026-11-07

## 背景

証明書を入れ替えるとき、サーバーが中間証明書を送り忘れたり、古い中間証明書を送り続けたりすることがある。OS やブラウザの検証器は、キャッシュや AIA（Authority Information Access）から足りない中間証明書を自分で補って検証を通すことがある。そのため、手元の環境では問題なく見えても、補完しないクライアントでは接続に失敗する。

cert の通常の出力はサーバー証明書だけを扱うので、この種の不備は見つけられない。

## 決定

- `--chain` を追加する。指定すると、サーバーが送ってきた証明書をすべて、送られた順に `chain` として出力する。補完はしない。
- 検査結果を `chainCheck` に `OK` または `NG: <理由>; <理由>...` の形で出す。検査は次の 2 つで、見つかった問題はすべて列挙する。
  - 発行者の一致: 先頭以外の各証明書について、直前の証明書の発行者と自身の主体者が一致すること。表示文字列ではなく名前の DER をそのまま比べる。
  - 有効期間: すべての証明書で、現在の時刻が NotBefore 以上 NotAfter 以下であること。
- 末尾の証明書の発行者は検査しない。比べる相手がなく、ルートまで送るサーバーも誤りではないため。ルートまで信頼できるかどうかは通常の検証（`-k` なし）の役割で、`--chain` はそれを変えない。`-k` とも併用できる。
- NG は表示のみとし、終了コードは 0 のままにする（0007 と同じ方針）。接続や解析に失敗した行には `chain` も `chainCheck` も付けない。チェーンの解析に失敗したときは、行のエラーにせず `chainCheck` に `NG: <理由>` を入れる。
- 指定しないときの出力は、どの形式でも従来と 1 バイトも変わらない。JSON では `chain` と `chainCheck` を省略し、md では列を足さない。
- フィンガープリントの SHA-256 は、すでに依存に入っている ring で計算する。

## 結果

- 補完に頼って通っていた中間証明書の欠落や期限切れを、証明書の入れ替え後に確認できる。
- 署名の検証はしないので、`--chain` の `OK` はチェーンが正しく署名されていることを保証しない。信頼の確認は通常の検証に任せる。
- 終了コードで失敗を検出したい場合は、JSON の `chainCheck` を見る必要がある。
