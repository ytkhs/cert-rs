# 0009. `--chain` の見直し（検証失敗時の表示・欠落の検出・名前の比較・解析失敗・シリアル番号）

- ステータス: 承認
- 日付: 2026-11-09

## 背景

0008 の `--chain` をレビューしたところ、次の問題が見つかった。

- `-k` なしでは、中間証明書の欠落や期限切れのせいで検証に失敗すると、その行はエラーになり `chain` が付かない。`--chain` で確かめたい状況ほど、チェーンが見えない。
- サーバー証明書 1 枚だけを送るサーバー（中間証明書の送り忘れの典型）を `OK` と判定する。0008 は末尾の証明書の発行者を検査しないためで、`--chain` の主な目的である欠落の検出ができていない。
- 名前の DER をそのまま比べているため、文字列の型（PrintableString と UTF8String）や大文字小文字だけが違う名前を不一致と判定する。RFC 5280 ではこれらは一致し、検証器も通すので、正しいチェーンが NG になる。
- チェーンのうち 1 枚でも解析に失敗すると、ほかの証明書の情報も捨てて空の `chain` にしていた。どの位置の証明書が壊れているかも分からない。

## 決定

- `--chain` を付け、`-k` を付けていないときは、OS の検証器を包んだ検証器で接続する。検証器が証明書を拒否しても理由を記録してハンドシェイクを続け、その接続で受け取ったチェーンを読む。その行は `error` に拒否理由を入れたうえで、サーバー証明書の情報と `chain`・`chainCheck` を付ける。ハンドシェイクの署名は元の検証器で確かめるので、相手が証明書の鍵を持っていることは保証される。接続の失敗やタイムアウトでは、0008 のとおり `chain` を付けない。
  - 拒否されたあとに検証なしで接続し直す方法は採らない。DNS ラウンドロビンやロードバランサーの配下では 2 回目に別のサーバーへつながることがあり、拒否理由と表示するチェーンが別々のサーバーのものになるため。
- 発行者の一致は、RFC 5280 7.1 の名前比較で判定する。RDN の並びと属性の種類は一致を求め、値は文字列として取り出し、前後と連続する空白を詰め、大文字小文字を無視して比べる（RFC 4518 のうち、実際の証明書で効く部分だけ）。文字列として取り出せない値はバイト列で比べる。
- 送られた証明書が 1 枚だけで、自己署名でもなく、発行者が OS の信頼ストアのどのルートの主体者とも一致しないときは `[0] issuer certificate not sent` を NG として出す。信頼ストアは `--chain` のときだけ、実行の開始時に 1 回読む。`-k` の有無で判定は変えない。
  - 「検証が通れば省く」とはしない。macOS などの検証器は、送られなかった中間証明書を AIA から自分で取ってきて検証を通すため、検証の成否では欠落を判断できない。
  - 社内 CA のルートから直接発行した証明書は、そのルートが OS に入っていれば OK になる。
  - 2 枚以上のときは、末尾が中間証明書でもルートを省いただけの正しい構成と区別しにくいため、0008 のとおり末尾の発行者は検査しない。
- 解析できない証明書があっても、ほかの証明書は表示する。解析できない証明書は SHA-256 だけを埋めたエントリにし、`chainCheck` に `[i] failed to parse certificate: ...` と位置を入れる。その証明書が関わるつながりと有効期間の検査は省く。先頭のサーバー証明書が解析できないときも、`--chain` では行をエラーだけで終わらせず `chain` と `chainCheck` を付ける。その行の `error` には解析エラー（検証の拒否理由があれば、それに続けて `; ` 区切りで）を入れ、CN などサーバー証明書の情報は空にする。`--chain` なしでは従来どおりエラー行にする。
- シリアル番号は openssl の `-serial` と同じく整数値として表示する。DER の符号用の先頭 `00` は付けず、負の値には `-` を付ける。
- md では、Chain 列の名前とほかの全列（ChainCheck を除く）で、表の区切りや HTML として解釈される文字（`|` `*` `_` `` ` `` `[` `]` `~` `\` `<` `>` `&`、改行）を無効化する。これまで SAN の `*` だけをエスケープしていたが、組織名やエラー文に `|` が入ると表が崩れていた。ChainCheck は固定の文言とパーサーのエラーだけでできているのでそのまま出す。
- 有効期間の検査に使う現在時刻は、実行の開始時に 1 回だけ取り、すべての行で共有する。

## 結果

- 検証に失敗したサーバーでも、どの証明書が欠けているか、期限が切れているかを `--chain` で確認できる。`-k` を付ける必要はない。
- `--chain` を付けたときに限り、`error` が空でない行にも証明書の情報が入ることがある。失敗の検出は引き続き `error` を見ればよい。
- `--chain` で `-k` を付けないときは、検証に失敗した接続でもハンドシェイクを最後まで行う。読むのは証明書だけで、データは送らない。
- `--chain` のときは OS の信頼ストアを読むので、起動が少し遅くなる（macOS で約 0.1 秒）。新しい依存として rustls-native-certs を加える（Linux では rustls-platform-verifier がすでに使っている）。
- md 出力は、`_` や `|` などを含む値でこれまでと見た目が変わる（`a\_b` のようにエスケープが入る）。
- 2 枚以上のチェーンで途中の中間証明書が抜けている場合（例えばクロスルートの中間証明書だけを送り忘れた場合）は、つながりが途切れていない限り検出できない。
- 名前比較は RFC 4518 を完全には実装していない（Unicode の正規化や、属性ごとの比較規則は省いている）。
