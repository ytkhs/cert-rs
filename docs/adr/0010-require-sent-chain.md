# 0010. 通常の検証でも中間証明書の送り忘れを検出する（あわせてエラー文を整える）

- ステータス: 承認
- 日付: 2026-11-12

## 背景

0001 では証明書の検証に rustls-platform-verifier（OS の検証器）を使うことにした。macOS や Windows の検証器は、サーバーが送らなかった中間証明書を AIA（Authority Information Access）から自分で取ってきて検証を通す。そのため incomplete-chain.badssl.com のように中間証明書を送り忘れたサーバーでも、`--chain` を付けなければエラーにならなかった。Linux の検証器は取りに行かないのでエラーになり、OS によって結果が違っていた。

中間証明書の送り忘れは、取得を行わないクライアント（多くの HTTP ライブラリ、組み込み機器、Android の古い版など）で接続できなくなる、よくある設定ミスである。cert はサーバー設定の確認に使うので、通常の実行で見つけられる必要がある。

また、OS の検証器のエラーは rustls が Debug 形式で包むため、`Other(OtherError("... certificate is expired: -67818"))` のように読みにくかった。

## 決定

- `-k` なしの検証を 2 段階にする。
  1. まず OS の検証器で検証する。ここで失敗したら、そのエラーを返す（失効の確認などは OS の検証器が行う）。
  2. 通ったら、取得を行わない検証器（rustls の webpki と OS の信頼ストアのルート）で、サーバーが送った証明書だけを使ってもう一度検証する。発行者が見つからない（UnknownIssuer）ときだけ、「サーバーが中間証明書を送っていない」というエラーにする。それ以外の失敗は無視し、OS の検証器の判断を優先する。
- OS の信頼ストアは rustls-native-certs で起動時に 1 回読み、2 段階目の検証と `--chain` の判定（0009）で共有する。1 つもルートを読めなかったときは 2 段階目を省く。
- ハンドシェイクの署名の確認は OS の検証器に任せる。
- OS の検証器のエラーは、包みを外して OS のメッセージを出す。macOS が末尾に付ける数値のエラー番号（`: -67818` など）は、利用者に意味がないので取り除く。
- あわせて、rustls の識別子のまま出ていた主なエラーを文にする（`NotValidForName`、`UnknownIssuer`、`Revoked` など）。TLS でないポートへの接続（`InvalidContentType`）と、サーバーがハンドシェイクを拒んだ場合（`HandshakeFailure` など。rustls が対応しない TLS 1.1 以前や古い暗号方式のサーバーで起きる）には、考えられる原因を添える。どれにも当たらないものは rustls の文をそのまま出す。
- 接続先のアドレスが複数あるときは、最後の 1 件だけでなく、失敗したすべてのアドレスと理由を並べる。IPv6 には届かず IPv4 では拒否された、といった原因を見落とさないため。

## 結果

- どの OS でも、中間証明書を送り忘れたサーバーが通常の実行でエラーになる。
- 失効した証明書の検出（revoked.badssl.com）は従来どおり OS の検証器が行う。
- `-k` なしの実行は、OS の信頼ストアを読むぶん起動が約 0.1 秒遅くなる（macOS）。
- OS の検証器は通すが、rustls-native-certs で読めないルート（例えば構成プロファイルで特別な扱いをしているもの）で発行された証明書は、送り忘れと誤判定するおそれがある。
- 2 段階目は名前の制約や鍵の用途なども webpki の規則で確認するが、UnknownIssuer 以外は無視するので、OS と webpki の細かな解釈の違いで誤ってエラーにすることはない。
