# 0011. スクリプトや AI が判断に使える JSON の欄と `--fail`

- ステータス: 承認
- 日付: 2026-11-12

## 背景

cert を AI エージェントやスクリプトから使うと、次の点で判断を誤りやすかった。

- エラーの種類が英語の文でしか分からない。文言を変えると、それを読んで判断している側の動きも変わってしまう。
- 期限が `2027-01-01 08:59:59 +0900 JST` のような表示用の文字列で、残り日数を自分で計算する必要がある。AI は日付の計算をよく誤る。
- 0007 で終了コードを常に 0 にしたため、終了コードで成否を判断する呼び出し側は失敗を見落とす。
- `--chain` の結果が `NG: [0] expired; [2] expired` のような文字列で、分解しないと扱えない。

## 決定

- JSON に次の欄を足す。table と md の出力、および既存の欄は変えない。
  - `errorKind`：エラーの種類を決まった値で表す。エラーがなければ `null`。値は README の一覧のとおりで、表示用のエラー文ではなく、元になった rustls のエラーから判定する。macOS の検証器が文で返すエラーは、末尾のエラー番号から判定する（-67818 expired、-67819 not_yet_valid、-67843 untrusted、-67815 weak_signature。それ以外は certificate_invalid）。
  - `notBeforeUtc`・`notAfterUtc`：RFC 3339 の UTC。チェーンの各証明書にも付ける。
  - `daysLeft`：NotAfter までの日数を切り捨てたもの。期限切れなら負の数。基準の時刻は実行の開始時に 1 回取ったもの（0009）を使う。
  - `chainProblems`：`--chain` のときだけ付ける。`index`・`kind`・`message` の配列。`chainCheck` は互換のために残す。
- 1 行に複数の失敗があるとき（検証の拒否とサーバー証明書の解析失敗）は、最初の失敗の種類を `errorKind` にする。
- `--fail` を追加する。指定したときだけ、`errorKind` が `null` でない行か `chainProblems` が空でない行があれば、終了コード 1 で終わる。出力は変えない。指定しないときは 0007 のとおり常に 0。
- `errorKind` に、案になかった `internal`（cert 自身の設定や処理の失敗）を加える。どの種類にも当てはまらないため。

## 結果

- 呼び出し側は `errorKind` と `daysLeft` で分岐でき、文言の変更に影響されない。これらの値は変えないことを約束し、表示用の欄（`error`、`notAfter` など）は今後も文言や書式を変えうるものとする。
- JSON の各行が長くなる。
- 終了コード 1 は「ホストが 1 つも指定されていない」場合と同じ番号だが、そちらは標準エラー出力にメッセージを出すので区別できる。
- macOS のエラー番号のうち、ここに挙げていないものは certificate_invalid になる。新しい番号に出会ったら、この一覧に足す。
