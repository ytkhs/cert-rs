# 0012. 診断用の情報、エラー行の接続先、既定の制限時間、DaysLeft の表示

- ステータス: 承認
- 日付: 2026-11-12

## 背景

0011 で JSON を判断に使えるようにしたが、次の点がまだ足りなかった。

- エラー行の `port` と `ip` が空で、どのポートや IP で失敗したかが JSON から分からない。
- 既定の制限時間が 3 秒で、応答の遅いサーバーや、macOS の検証器が中間証明書を取りに行く時間で、時間切れになりやすい。時間切れは「サーバーが落ちている」と誤解されやすい。
- 「古いクライアントで繋がらない」といった問題を調べるのに、合意した TLS のバージョンや暗号方式、鍵の種類と長さ、署名方式が分からない。
- 期限までの日数（daysLeft）が JSON にしかなく、表で見る人は日付から自分で数える必要がある。

## 決定

- エラー行にも、指定されたポートを入れる。TCP の接続まで済んでいれば、その IP も入れる。
- 既定の制限時間を 10 秒にする。時間切れのエラー文には、そのときの制限時間と、`-s` で延ばせることを添える。
- JSON に `tlsVersion`・`cipherSuite`・`keyType`・`keyBits`・`curve`・`signatureAlgorithm` を足す。
  - 鍵長は自前で計算する。x509-parser の `key_size` は RSA で先頭に 0 のバイトがある前提で作られていて、それ以外では 0 を返すため。EC は名前付き曲線から長さを決める（点のバイト長からだと P-521 が 528 になるため）。DSA はパラメーターの素数 p の長さを使う（公開値 y は p より数ビット短いことが多いため）。パラメーターがなければ `null` にする。
  - 署名方式は OpenSSL と同じ短い名前にし、知らない方式は OID の数字の形で出す。
- table に `DaysLeft:` の行、md に `DaysLeft` 列を足す。エラー行では空にする。

## 結果

- table と md の出力が 1 項目増える。md の列は 1 つ増え、table は NotAfter の次に 1 行増える。
- 既定の制限時間が延びたので、応答しないホストを含むと、全体の完了まで最大 10 秒待つ。急ぐときは `-s` で短くする。
- 0011 と同じく、JSON の新しい欄の値は変えないことを約束する。
